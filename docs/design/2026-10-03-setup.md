# Setup: repository, tracker, Godot project and round three

**Date:** 2026-10-03. **Agreed with:** Ben. **Settles:** the Setup milestone in `docs/game-bible.md` ("Milestones", item 1), and replaces part 1 of `SETUP.md`.

This spec covers the one-time setup only. The combat core (`docs/architecture.md`) and the Milestone 1 build each get their own spec.

## What Ben decided

| Point | Decision |
|---|---|
| Repository | New public repository `beben-games/dghf`, on Ben's personal account. The name is a placeholder until the team picks a title. It can move to an organisation later. |
| Relation to `beben-games/2d-game` | Separate project. Its PixelLab art pipeline may be reused (see "Art pipeline"). |
| Godot version | 4.7.2 stable, decided by Ben as build owner. |
| Collaborators | T and E have no GitHub accounts yet. Round three asks them to create one, and Ben invites them afterwards. |

## What stays proposed or open

- **Sprite size (Proposed, Ben, 2026-10-03).** Characters about 26 by 38 pixels, the size of LuizMelo's Medieval Warrior Pack 3 (https://luizmelo.itch.io/medieval-warrior-pack-3). T prefers larger sprites in the direction of Marvel vs SNK, so this goes to round three and the weekly meeting. Until the team decides, placeholder art and test scenes use this size.
- **Internal resolution (Proposed).** 480 by 270. A 38-pixel character is about a seventh of the screen height, which leaves room for a crowd.
- **Licence (Open).** No `LICENSE` file until round three chooses between MIT and GPL. The README says so.

## 1. Repository

- `git init` in this folder, with `main` as the default branch. The starter kit is the first commit and the only direct push to `main`.
- `game-repo-starter.zip` is added to `.gitignore` and not committed. `.DS_Store` is already ignored.
- `main` is protected: changes need a pull request. No approval is required, because GitHub doesn't let an author approve their own pull request and Ben is the only member for now.

## 2. Tracker

- `scripts/setup-github.sh` creates the labels and the five milestones.
- `scripts/create-milestone-1-issues.sh` creates the Setup and Milestone 1 issues. Before it runs, the "Create the Godot project" issue text is changed to name Godot 4.7.2, and one issue is added: "Port the PixelLab art pipeline" (see below).
- A project board named "Game" is created, linked to the repository, with the statuses Todo, In progress, In review and Done.
- Two steps need Ben in the browser: `gh auth refresh -s project` before the board is created, and turning on the board's **Auto-add** workflow, which has no API.

## 3. Godot project

Done as the "Create the Godot project" issue, on a branch, through a pull request that Ben merges.

- `project.godot` created with Godot 4.7.2.
- The folder layout from `CLAUDE.md`: `scenes/`, `systems/`, `data/`, `assets/` and their subfolders, each kept in git with a `.gitkeep` file.
- An empty main scene, so the project opens and runs.
- Viewport 480 by 270 with whole-number scaling and nearest-neighbour filtering. A comment in the pull request says this is the proposed resolution, not a decided one.
- Checked by importing and running the project headless with the installed Godot before the pull request is opened.

## 4. Round three in the Google Doc

The six existing questions and E's answers stay untouched. Claude drafts the additions, Ben reviews them, and only then are they added to the doc.

**Onboarding**
- Create a GitHub account and write your username here.
- Install Godot 4.7.2 stable. Done?
- What machine will you play and test on (model, year, graphics card if you know it)?

**Questions that need all three**
- Sprite size: small characters like Medieval Warrior Pack 3 (about 26 by 38 pixels, more enemies fit on screen) or larger ones (more detail, fewer enemies)?
- Depth: free movement up and down the screen, or 2 to 3 lanes like Guardian Heroes?
- Special moves: fighting-game motions (quarter circles), direction plus button, or motions for spells only?
- How many enemies on screen at once: 30, 100 or 300?
- Co-op: gamepads required, or must two players be able to share a keyboard?

Ben's answer to the existing PixelLab question is already known: his tier 2 subscription generates the team's assets.

## 5. Art pipeline

Ben has a PixelLab tier 2 subscription (5,000 generations a period), and `beben-games/2d-game` has a working pipeline for it in `tools/art/`: a REST client, job files, a budget check, palette enforcement, sheets and previews, with the rules in its `docs/ART.md`.

- Porting it is its own issue in Milestone 2, not part of setup. A style probe at the proposed sprite size is its first use, and gives the team real images to judge the size question by.
- The API key stays in Ben's macOS keychain, as in `2d-game`. Nothing secret enters this repository.
- The allowance is shared with `2d-game`, so the port includes a budget split between the two projects.
- `CLAUDE.md` currently says assets come through the PixelLab MCP server in each person's settings. The port issue proposes how the two fit together, and that change goes to the team.
